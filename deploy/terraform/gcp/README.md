# Wiggle on GCP — GKE + Cloud SQL PostgreSQL (Terraform)

The GCP sibling of the [AWS module](../aws). Stands up a production-shaped Wiggle control plane:

- a **VPC** (VPC-native subnet with pod/service secondary ranges, Cloud NAT for egress),
- a **regional GKE** cluster with private nodes + an autoscaling node pool,
- a **Cloud SQL PostgreSQL** instance on a **private IP** (via Private Services Access — no public IP,
  no Auth Proxy sidecar), and
- the **Wiggle Helm chart** ([`deploy/helm/wiggle`](../../helm/wiggle)) deployed against Cloud SQL —
  several server nodes that **cluster on the shared database** (the HA "cluster on one DB" posture; no
  coordinator).

The Wiggle image is the signed, non-root, distroless one; the pod runs hardened by default straight
from the chart.

## Prerequisites

- Terraform >= 1.6, the **`gcloud` CLI** authenticated (`gcloud auth application-default login`), and
  `kubectl`.
- A GCP project with billing; the module enables the APIs it needs (compute, container, sqladmin,
  servicenetworking).

## Use

```bash
cp terraform.tfvars.example terraform.tfvars   # set `project` (required)
terraform init
terraform apply
```

> **First apply:** the `kubernetes`/`helm` providers authenticate to a cluster that doesn't exist yet,
> which Terraform can't fully resolve during the first plan. If apply errors on the Kubernetes
> resources, stage the infra first, then re-run:
> ```bash
> terraform apply -target=google_container_cluster.this -target=google_container_node_pool.default -target=google_sql_user.wiggle
> terraform apply
> ```

Then point `kubectl` at it (the command is an output):

```bash
$(terraform output -raw kubeconfig_command)
kubectl -n wiggle get pods
kubectl -n wiggle port-forward svc/wiggle 8080:8080   # reach gRPC on localhost:8080
```

## Outputs

| Output | Meaning |
|---|---|
| `cluster_name` | the GKE cluster |
| `kubeconfig_command` | `gcloud container clusters get-credentials …` |
| `cloudsql_private_ip` | Cloud SQL private IP (the JDBC host) |
| `wiggle_service` | in-cluster gRPC address (`wiggle.wiggle.svc:8080`) |
| `database_password_secret` | the k8s Secret holding the JDBC credentials |

The database password is generated by Terraform, stored in a Kubernetes Secret (keys `url`/`user`/
`password`, consumed by the chart's `storage.jdbc.existingSecret`), and kept in Terraform state — use
an **encrypted remote backend** (a GCS bucket) for anything real.

## Cost & hardening notes

- Defaults (regional GKE with `e2-standard-4` nodes, `db-custom-2-8192` REGIONAL Cloud SQL) are
  production-ish, not free-tier. Shrink `node_*` / `db_*` for a trial.
- The GKE control-plane endpoint is public (`enable_private_endpoint = false`); add
  `master_authorized_networks` (or a private endpoint + bastion) for production.
- `deletion_protection = false` on the cluster and Cloud SQL is convenient for demos — enable both
  where the data/cluster matters.

## Not yet included

- A **coordinator** deployment (cellular/multi-tenant) on the JDBC coordinator store — needs a
  coordinator Helm chart; this module is the single-cluster posture.
